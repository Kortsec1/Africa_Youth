# Windows 아티팩트를 활용한 Shadow AI 사용 정황 분석

최종 연구 보고서 · 2026-11-27

## 1. 연구 목적

이 연구에서는 Windows에 남는 파일 정보, 브라우저 기록, 사용자 행동 로그와 네트워크 기록으로 AI 서비스 사용 정황을 어디까지 설명할 수 있는지 살펴봤다. AI 사이트에 접속한 사실과 실제로 질문이나 파일을 보낸 사실을 구분하는 데 중점을 뒀다.

연구는 탐지 규칙, Windows 포렌식, AI 아티팩트, 엔드포인트 수집, 네트워크 탐지의 다섯 분야로 나누어 진행했다. 마지막 단계에서는 기존 결과와 공개 가능한 자료를 정리하고, 자료를 직접 조회할 수 있는 Python·Streamlit 프로그램을 만들었다. 프로그램은 연구 결과를 설명하는 보조 도구다.

## 2. 연구 방법

각 분야의 실험 보고서와 코드를 확인하고 실제 관측 자료, 공유용 파생 자료, 합성 데이터를 구분했다. 공유용 파생 자료는 원시 로그에서 개인정보 등 일부 필드를 제거한 파일이다. 실험에서 더미 파일이나 합성 문장을 사용했더라도 실제 수집기가 기록한 로그는 실측 자료로 분류했다. 코드로 만든 가상 이벤트와는 구분한다.

통합 과정에서는 새로운 Windows 실험을 반복하지 않았다. 기존 자료의 시간과 출처를 보존하고, 확인되지 않은 장치·사용자·발생 시각은 비워 뒀다. 상세한 파일 목록과 입력 형식은 [통합 문서](integration.md)에 정리했다.

## 3. 분야별 연구 결과

| 분야 | 주요 결과 | 확인 범위 |
|---|---|---|
| 탐지·상관분석 | 시간, 장치, 사용자, 발생 순서를 조건으로 R01~R05 규칙 구현 | 합성 이벤트에서 예상 결과를 검증했다. 실제 탐지 성능은 측정하지 않았다. |
| Windows 포렌식 | 파일 생성·열람·수정·복사·삭제 실험의 메타데이터 비교 | 단일 호스트에서 동작별 1회 수행한 결과다. MFT·USN 원본 파싱과 LNK·JumpList 연계는 미검증이다. |
| AI 아티팩트 | History 분석기 구현, ChatGPT의 미전송·전송 문구 잔존 관측 | 분석기는 합성 DB로 검증했다. 실제 History 조회는 잠금으로 실패했고, 파일 업로드 성공은 확인하지 못했다. |
| 엔드포인트 | Clipboard 변경, 활성 창, 프로세스 활동 수집과 웹 paste 관측 | 주요 동작을 확인했지만 창·탭 횟수 대조와 전체 행위 연결은 완료하지 못했다. |
| 네트워크 | DNS 캐시와 TCP 연결을 수집해 접속 정황 비교 | DNS 누락과 공용 IP의 한계를 확인했다. 접속만 한 경우와 질문을 보낸 경우를 이 수집 방식으로 구분하지 못했다. |

상관분석 연구의 확장 합성 사례에서는 시간 범위를 60초에서 300초로 넓혔을 때 관련 정황 탐지가 1건에서 2건으로 늘었지만, 무관한 사건의 오연결도 1건에서 3건으로 늘었다. 시간상 가까운 기록을 연결하는 것만으로는 실제 관련성을 확정하기 어렵다.

엔드포인트 연구에서는 복사 1회 후 붙여넣기 3회를 수행했다고 보고한 실험에서 Clipboard 변경 알림이 1건 남았다. 별도의 Chrome 확장 실험에서는 붙여넣기 조건에서 paste 이벤트 1건, 클릭만 한 조건에서 0건을 관측했다. Clipboard 변경 횟수와 붙여넣기 횟수는 다르며, paste 이벤트가 있어도 질문 전송을 뜻하지 않는다.

AI 아티팩트 연구에서는 전송하지 않은 문구도 로컬 저장소에 남았다. 전송한 질문과 응답은 별도 화면 관측으로 보고했지만, 저장소의 문구 바이트만으로 전송 여부를 판단할 수는 없었다. 네트워크 연구에서도 접속만 한 경우와 입력·전송한 경우의 후보 IP 종류와 연결 횟수가 같았다. 이 비교는 각 1회여서 일반화에는 한계가 있다.

## 4. 결과를 함께 해석하는 방법

파일 메타데이터는 파일 상태를, 브라우저 History는 방문 기록을 설명한다. 활성 창과 프로세스 기록은 당시 실행 환경을 보완하고, 웹 paste 로그는 추가 계측이 이루어진 페이지에서 붙여넣기 이벤트가 발생했음을 보여준다. DNS와 TCP는 서비스 접근 후보를 찾는 데 사용할 수 있다.

여러 자료를 함께 보면 단일 기록만 볼 때보다 조사할 범위를 좁힐 수 있다. 다만 이번 자료는 서로 다른 날짜와 실행에서 얻었다. 이들을 하나의 파일 읽기·복사·붙여넣기·전송 사건처럼 이어 붙이지 않았다.

| 자료에서 확인한 사실 | 구분해야 할 주장 |
|---|---|
| 파일의 접근 시각 값 | 특정 사용자가 파일 내용을 읽거나 업로드했다는 주장 |
| AI 서비스 방문 기록 | 질문 전송이나 업무 자료 사용 여부 |
| Clipboard 상태 변경 | 붙여넣기 대상과 횟수 |
| 웹 paste 이벤트 | 실제 입력 성공과 질문 전송 |
| 저장소의 문구 잔존 | 서버 전송 완료 |
| DNS 캐시·TCP 연결 | 요청 내용과 파일 업로드 성공 |

## 5. 통합 프로그램

프로그램은 기존 JSON·JSONL을 읽어 시간순 표와 원본 근거를 표시한다. 사용자가 파일 메타데이터, Clipboard 실험 2종, 프로세스 실험, 웹 paste 실험 2종 중 하나를 선택하면 기록을 조회할 수 있다. 상세 보기에는 원본 필드, 파일 해시, 행 번호 또는 JSON 경로, 자료 성격과 판단 한계를 표시한다.

시간대가 있는 값은 UTC로 변환한다. 파일 메타데이터처럼 별도 관측 시각이 없는 자료는 시각 미확정 표에 두고 생성·수정·접근 시각은 원본 상세에서 확인하도록 했다. 없는 시간을 임의로 채우지 않았다.

합성 규칙 시연은 별도 메뉴로 구성했다. 기존 `analyze.py`가 합성 입력만 허용하므로 원래 샘플을 그대로 사용하고, 30·60·300초 조건에서 결과와 근거 이벤트를 보여준다. 사용자가 불러온 실측 파일을 합성 규칙에 넣는 기능은 없다.

구현은 화면, 데이터 변환, 기존 규칙 호출로 나눴다. 별도 DB나 API 서버 없이 메모리에서 처리한다. 실제 History 방문 추출본, 활성 창 원시 로그, DNS/TCP 로그는 저장소에 없어 기본 시연에는 포함하지 않았다. 기존 형식의 파일을 불러오는 경로는 있지만 해당 자료의 실측 연동은 검증하지 않았다.

실행 명령과 파일 구성은 [프로그램 안내](../integration/README.md)를 참조한다.

## 6. 프로그램 검증

2026-11-27에 Python 3.14.6, Streamlit 1.67.0 환경에서 [기능 확인 코드](../integration/check.py)를 실행했다. 아래는 프로그램 검증 결과이며 Windows 수집 실험을 다시 수행한 결과는 아니다.

| 확인 항목 | 결과 |
|---|---|
| 기존 자료 6종 읽기 | 통과. 메타데이터 4행, 공유 JSONL은 각각 7·2·2·4·3행 확인 |
| 시간·누락값 처리 | UTC 변환과 시간대 없는 값의 시각 미확정 처리 확인 |
| 원본 출처 | 행 위치와 파생본 표기, 누락된 장치 정보 보존 확인 |
| 잘못된 JSON·빈 입력 | 오류와 빈 결과를 구분하는 처리 확인 |
| 화면 동작 | Streamlit AppTest에서 자료 메뉴와 30·60·300초 선택 통과 |
| 기존 규칙 재사용 | 기본 60초 결과가 기존 output.json과 일치 |

기본 규칙 결과는 R01 3건, R02 1건, R05 1건이다. 하나의 이벤트가 여러 규칙에 포함될 수 있으므로 이를 사용자 행동 5건으로 해석하지 않는다. 통합 검토 단계에서 기존 상관분석 테스트 7개와 History 합성 검사 6개도 통과했다.

브라우저 화면의 수동 육안 검사, Windows 수집기 재실행, 실제 파일 업로드 실험은 이번 통합 단계에서 하지 않았다. 따라서 이번 검증으로 말할 수 있는 범위는 기존 자료 조회와 합성 규칙 결과 재현까지다.

## 7. 연구의 한계

실험 수가 적고 공통 환경에서 전체 흐름을 수집한 자료가 없다. 실제 사용 환경의 탐지율과 오탐률을 제시하기 어렵고, 합성 사례의 수치를 실제 성능으로 환산할 수도 없다.

공개 로그에서는 장치명, 사용자 정보, 창 제목 등 일부 필드가 제거됐다. 원본을 보유하지 않은 상태에서 사용자나 프로세스의 동일성을 완전히 확인하기 어렵다. PID는 재사용될 수 있고 네트워크 IP도 여러 서비스가 공유할 수 있다.

관측 시각과 실제 행동 시각에도 차이가 있다. 파일 접근 시각은 환경 설정의 영향을 받으며, DNS/TCP의 폴링 시각은 질의나 연결이 처음 발생한 시각을 보장하지 않는다. 시간대를 맞추는 작업만으로 장치 간 시계 오차가 해결되지는 않는다.

원문을 수집하지 않는 방식은 개인정보 노출을 줄이는 데 도움이 되지만 파일 내용과 Clipboard, 붙여넣은 문장, 전송 내용을 직접 비교하는 데 제약이 있다. 이번 연구에서는 파일부터 전송까지의 동일성을 자동으로 추적하지 않았다.

## 8. 결론

Windows와 브라우저에 남는 기록으로 AI 서비스 접근과 주변 행동의 일부를 설명할 수 있었다. 파일 메타데이터, 방문, Clipboard 변경, paste, 네트워크 연결은 각각 다른 사실을 나타내므로 구분해서 해석해야 한다. 특히 시간상 인접한 기록이나 로컬 저장소에 남은 문구만으로 질문 전송과 파일 업로드를 확정할 수 없었다.

최종 산출물은 다섯 분야의 연구 결과, 통합 문서, 기존 자료 조회 및 합성 규칙 시연 프로그램이다. 프로그램에서 출처와 판단 한계를 함께 확인하도록 구성했다. 추가 확인이 필요하다면 같은 장치에서 하나의 짧은 실험을 수행하고 행동 시각과 수집 로그를 대조하는 정도부터 시작할 수 있다. 이번 결과는 현재 확보한 자료와 검증 범위 안에서 정리했다.

## 9. 발표 시연 순서

1. 파일 메타데이터를 열고 생성·수정·접근 시각과 관측 시각의 차이를 설명한다.
2. Clipboard 복사 실험과 웹 paste 양성·음성 자료를 각각 보여준다. 서로 다른 실험이라는 점을 함께 설명한다.
3. 합성 규칙 시연에서 기본 60초 결과와 근거 이벤트를 확인한다.
4. 실측 Timeline과 합성 분석을 분리한 이유, 전송·업로드 판단의 한계로 마무리한다.
