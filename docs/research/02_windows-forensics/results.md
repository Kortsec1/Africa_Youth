# 실험 결과

2026-11-15에 Windows NTFS 환경에서 더미 파일의 생성, 열람, 수정, 복사, 삭제를 각 1회 수행했다. 생성·수정·접근 시각을 비교했고, 복사본의 파일 ID와 SHA-256을 원본과 대조했다. 브라우저 및 AI 서비스 연계 실험은 미실시다.

## 1. 실험 환경

| 항목 | 값 |
| --- | --- |
| 운영체제 | Windows, OS 빌드 `10.0.26200.0` |
| 파일 시스템 | NTFS, 동일 볼륨 내 복사 |
| 도구 | PowerShell 7.6.5, `fsutil` |
| 대상 | 더미 텍스트 파일 `forensics-demo.txt`, 복사본 `forensics-demo-copy.txt` |
| 시간 기준 | UTC, 표는 밀리초까지 표시 |

## 2. 실험 목적

파일 작업 전후의 메타데이터를 비교해 각 동작이 어떤 흔적을 남기는지 확인한다. 이 결과를 바탕으로 AI 서비스 방문 시각과 로컬 파일 활동을 타임라인에서 연결할 때 사용할 단서와 추가로 검증할 항목을 정리한다. [Windows Forensics README](https://github.com/Kortsec1/Africa_Youth/blob/main/docs/research/02_windows-forensics/README.md)

## 3. 실험 과정

1. 더미 파일을 생성하고 PowerShell로 생성·수정·접근 시각과 크기를 기록했다.
2. 파일 내용을 읽은 뒤 같은 항목을 조회했다. 이어서 텍스트를 추가하고 다시 기록했다.
3. `Copy-Item`으로 같은 폴더에 복사본을 만들었다. 두 파일의 SHA-256과 `fsutil file queryfileid` 출력값을 비교했다.
4. 복사본을 대상으로 `fsutil usn readdata`를 실행했다. 이후 `Remove-Item`으로 복사본을 삭제하고 해당 경로의 존재 여부를 확인했다.

## 4. 실험 결과

| 동작 | 파일명 | 생성 시각 | 수정 시각 | 접근 시각 | 크기 |
| --- | --- | --- | --- | --- | ---: |
| 생성 | `forensics-demo.txt` | 12:11:54.778 | 12:11:54.778 | 12:11:54.778 | 14 B |
| 내용 열람 | `forensics-demo.txt` | 12:11:54.778 | 12:11:54.778 | 12:11:55.943 | 14 B |
| 내용 수정 | `forensics-demo.txt` | 12:11:54.778 | 12:11:57.066 | 12:11:57.066 | 23 B |
| 복사 | `forensics-demo-copy.txt` | 12:11:58.190 | 12:11:57.066 | 12:11:58.192 | 23 B |

- **열람.** 생성·수정 시각과 크기가 유지됐고 접근 시각이 갱신됐다. 이 값은 해당 호스트에서 PowerShell로 읽었을 때의 관측값이다.
- **수정.** 생성 시각은 유지됐고 수정 시각이 갱신됐다. 파일 크기는 14 B에서 23 B로 늘었다.
- **복사.** 복사본의 생성 시각은 복사 시점으로 기록됐고 수정 시각은 복사 직전 원본과 같았다. SHA-256은 일치했고 파일 ID는 각각 원본 `0x000000000000000000050000000b9f16`, 복사본 `0x000000000000000000040000000b9f19`로 달랐다. 동일한 내용을 가진 별도 파일이 생성된 것을 확인했다.
- **삭제.** 삭제 후 복사본 경로가 존재하지 않았다. 삭제 전 `fsutil usn readdata` 출력에서 복사본의 파일 참조 번호와 이름은 확인했으나 `Reason`은 `0x0`이었다. USN 저널의 `FileDelete` 기록과 삭제 후 `$MFT` 레코드 상태는 미검증이다.

## 5. 확인된 한계

- 단일 호스트에서 동작별 1회 수행했다. 이번 접근 시각 갱신 결과는 Windows 설정과 접근 방식에 따라 달라질 수 있다.
- 파일 메타데이터는 PowerShell로 조회했다. `$MFT` 원본을 파싱해 `$STANDARD_INFORMATION`과 `$FILE_NAME`을 비교하는 작업과 `$UsnJrnl:$J` 이벤트 확인은 미실시다.
- 탐색기나 응용 프로그램으로 문서를 열지 않아 Recent LNK와 JumpList 생성 조건은 미검증이다. 스크립트 삭제는 휴지통 이동과도 구분해야 한다.
- AI 페이지 방문과 파일 활동의 시각이 가까우면 조사 후보를 좁힐 수 있다. 실제 전송 여부를 판단하려면 파일 선택 후 취소와 전송을 비교하고, 서비스에서 확인 가능한 전송 상태나 엔드포인트 기록을 교차 확인해야 한다.

## 6. 추가 연구 사항

1. Windows VM에서 탐색기로 문서를 열고, 브라우저에서 더미 파일을 **선택 후 취소**, **선택 후 전송**, **드래그 앤 드롭으로 전송**하는 시나리오를 각각 반복한다. 동작 시각과 결과를 별도로 기록하고 Recent LNK, JumpList, 브라우저 기록을 비교한다.
2. AI 서비스에서 테스트 파일을 다운로드한 뒤 브라우저 다운로드 이력의 파일명·경로·시각과 `$MFT`·`$UsnJrnl:$J`의 생성·이름 변경 기록을 대조한다.
3. 삭제는 휴지통 이동과 휴지통을 거치지 않는 삭제를 각각 수행한다. `$I`·`$R` 파일, USN 이벤트, `$MFT` 레코드 상태를 확인하고 시나리오별 원본 또는 파싱 결과를 `samples/`에 보관한다.
