# AI 서비스 아티팩트 분석 결과

기준일: 2026-11-16. 관련 이슈: #5.

## 1. 실험 환경과 수행 범위

실제 ChatGPT 접속·미전송 문구 입력·다른 질문 전송을 수행하고 IndexedDB 파일에서 문구 잔존을 확인했다. [실제 실험 결과·DB 캡처](evidence/live-20261116/README.md)에 실측 근거와 한계를 기록했다. ChatGPT 단일 실행이며 Claude/Gemini, 업로드 성공, 종료 후 비교와 반복 실험은 미완료다. 아래 3절의 합성 검증은 별도 분석기 검증이다. 4절의 기존 미실행 매트릭스는 전체 계획 기준이며 이번 ChatGPT S01/S02/S03 단일 실측은 연결 문서의 결과로 갱신한다.

| 항목 | 실제 수행 내용 |
|---|---|
| 로컬 실행 환경 | Windows PowerShell, Python 3.14.0, Python 내장 SQLite 3.50.4 |
| 분석 입력 | 코드로 만든 임시 SQLite DB. 사용자 History 미수집 |
| 브라우저 | 연결된 Chrome으로 GitHub·공식 문서 열람. AI 테스트 브라우저 버전 미측정 |

| 프로젝트 확보 | 사용자 제공 Downloads의 전체 프로젝트를 읽고 작업 폴더에 사본 생성 |
| 원격 반영 | 사용자 지시에 따라 commit/push/PR/이슈 변경 미수행 |

## 2. 실험 목적과 과정

목적은 서비스 접속과 질문 전송, 파일 선택과 업로드 성공을 서로 다른 주장으로 구분하는 것이다. [실험 계획](experiment-plan.md)의 S00~S10에 따라 실제 VM 실험을 이어갈 수 있도록 설계했다.

분석기 검증은 (1) 임시 History 스키마 생성, (2) 정상/위장 도메인·반복 방문 삽입, (3) 개별 방문 추출, (4) UTC 변환·원본 해시 검사, (5) WAL 미체크포인트 방문 추가 후 읽기, (6) 손상 DB 거부 순서로 수행했다. 생성 입력과 기대값은 `scripts/selftest.py`에서 재현된다. 합성 DB는 테스트 종료 시 폐기하며 아래 JSON은 실행 결과만 보존한다.

```powershell
python .\docs\research\03_ai-artifacts\scripts\selftest.py
```

## 3. 실제 실행한 도구 검증 결과

실행 로그: [samples/selftest.json](samples/selftest.json). 최종 실행 UTC: `2026-11-16T10:59:40.123511+00:00`. 6개 검사 통과.

| 검사 | 관측 결과 | 해석 범위 |
|---|---|---|
| 정확한 host·scheme 판별 | 정상 5개 URL의 6회 방문 추출. 유사 접미사, query 내 도메인, userinfo 위장, file scheme 제외 | 합성 레코드 필터 검증 |
| 시각 변환·반복 방문 | Chromium 1601 epoch 마이크로초를 `2026-11-16T00:00:00+00:00`, 반복 방문을 1초 뒤로 추출 | 합성 시각 계산과 개별 visits 유지 |
| 과잉 추론 방지 | 출력 action은 모두 `service_visit_record` | 출력이 질문·업로드를 자동 확정하지 않음 |
| 주 DB 변경 여부 | 분석 전/후 SHA-256 일치 | 테스트 주 DB에 한정. 디스크 전체 불변성 의미 아님 |
| WAL 읽기 | 연결이 열린 상태에서 커밋한 7번째 방문 추출 | 분석기가 WAL을 무시하지 않음. 실제 수집 일관성은 별도 |
| 손상 DB 처리 | 비SQLite 입력에서 DatabaseError | 잘못된 입력을 정상 미검출로 보고하지 않음 |
| PowerShell 수집기 | PowerShell AST 구문 검사 오류 0건 | 문법 검사만 완료. 실제 실험 프로필 수집 실행 미검증 |

최초 selftest에서 SQLite 연결이 닫히지 않아 Windows 임시파일 정리에 실패했다. 분석기에 명시적인 연결 종료를 적용한 뒤 위 6개 검사를 재실행해 통과했다. 실패를 서비스 아티팩트 결과로 집계하지 않는다.

## 5. 확인된 한계

- 현재 확인된 사실은 프로젝트 요구, 공식 저장 경로/보존 원리, 합성 분석기 검증이다. 특정 AI 서비스의 질문·파일 본문이 특정 LevelDB 키에 남는지는 확인하지 못했다.
- 수집기는 선정 파일 복사 도구이며 레지스트리·MFT/USN·메모리·TLS 내용을 수집하지 않는다. 실행 중 상태 및 정상 종료로 사라지는 상태는 별도 절차가 필요하다. 수집기 실제 프로필 검증도 남아 있다.
- 분석기는 Chromium History의 `urls`/`visits` 스키마만 대상으로 한다. 스키마 변경 시 오류를 확인해야 한다. 캐시/LevelDB/삭제 레코드 복구·Firefox·데스크톱 앱 분석은 구현하지 않았다.
- URL·제목·프로필 경로도 민감할 수 있다. 분석 출력은 로컬 검토 후 공개용 마스킹본을 만든다. 원본 History나 HAR를 그대로 커밋하지 않는다.
- SQLite 버전 3.50.4로 단일 writer/reader 합성 검증을 수행했다. 최신 공식 문서의 WAL 동시 쓰기/체크포인트 관련 수정 사항과 별개로, 이 도구는 원본에 쓰기나 체크포인트를 수행하지 않는다.
