# 네트워크 기반 AI 사용 탐지 실험 결과

프로젝트: Windows 포렌식 아티팩트 기반 Shadow AI 사용 행위 탐지 및 분석
담당: 이채원 / 실험일: 2026-11-25 ~ 2026-11-26 / 저장소 정리: 2026-11-26
현재 상태: 기본 수집 PoC와 주요 접속 실험 완료. 입력·전송 비교는 1회씩만 수행(구분되지 않음). 다른 AI 서비스, 로그 기반 수집 비교는 미수행. 완성된 탐지 시스템이 아니다.

## 1. 연구 목표와 결과 요약

### 1.1 목표
DNS 및 네트워크 연결 정보로 생성형 AI 서비스 접근을 식별하고, 네트워크 증거로 확인할 수 있는 범위와 없는 범위를 구분한다.

### 1.2 주요 결과
- 이 PC의 Chrome에서 ChatGPT에 접속했을 때 **Windows DNS 캐시에는 `chatgpt.com`이 대부분 남지 않았다.** 최초 시험 1회를 제외한 8회(로그인 상태 2회 포함) 모두 기록이 없었다.
- 같은 실행에서 **TCP 연결 기록(프로세스 + 원격 IP)에는 매번 ChatGPT로 보이는 Cloudflare IP 연결이 나타났다.** 이 IP는 도메인 근거가 있는 것(2개)과 시각 일치로 추정한 것(3개)이 섞여 있다.
- 일반 사이트 접속에서는 위 IP로의 연결이 나타나지 않았다(2회). 다만 같은 Cloudflare 대역의 다른 IP는 일반 사이트에서도 나타나, **대역 단위 판정은 오탐을 낸다.**
- 로그인 후 합성 문장을 입력·전송해 응답을 받은 1회(S2b)와 접속만 한 1회(S2a)를 비교했을 때, ChatGPT 관련 IP 연결의 종류와 횟수가 같았다. 이 수집 방식으로는 입력·전송 여부가 구분되지 않았다(각 1회, 재현 미확인).
- 네트워크 기록으로는 "접속 정황"만 확인된다. 질문 내용, 파일 업로드, 실제 사용 행위는 확인되지 않는다.

### 1.3 과업 충족 현황

| 해야 했던 일 | 지금까지 한 일 | 남은 부분 |
|---|---|---|
| AI 도메인·DNS 특성 조사 | ChatGPT 관측 IP 확인, Cloudflare 계열 IP 사용 확인 | 다른 AI 서비스 도메인·IP 미관측 |
| Windows 네트워크 정보 수집 방법 조사 | DNS 캐시, TCP 연결 목록 수집 PoC 작성·실행 | DNS-Client 로그, Sysmon, ETW 미수행 |
| AI 접속 시 DNS·연결 이벤트 분석 | ChatGPT 접속 8회 분석(로그인 상태 2회 포함) | 다른 AI 서비스 미수행 |
| 일반 웹사이트와 비교 | 일반 사이트 접속 2회 비교 | 표본 작음 |
| 접근 증거와 실제 사용 행위 구분 | 3.1 표로 정리, 입력·전송 1회 비교(구분되지 않음) | 반복 횟수 부족, 패킷 수준 비교 미수행 |
| 오탐·기술적 한계 정리 | 대역 단위 오탐, DNS 캐시 누락 확인 | 정량 정확도는 소표본 |

## 2. 실험 방법과 관측 결과

### 2.1 실험 환경
- OS: Windows 11 Home 25H2 (빌드 26200.10075)
- 브라우저: Chrome 158.0.8127.37 (공식 빌드, 64비트)
- 수집: `poc/collect_network.ps1` (1초 간격 폴링, DNS 캐시 + TCP 연결). 관측 시각은 폴링 시각이라 실제 질의·연결 시각과 최대 1초 오차가 있다.
- 권한: 수집 스크립트는 관리자 PowerShell에서 실행(`ipconfig /flushdns` 성공으로 확인), Chrome은 일반 권한으로 실행
- DNS 서버: DHCP 자동, 국내 통신사 계열 DNS 서버로 추정(주소 앞부분 기준). 시스템 DoH 설정은 확인되지 않음
- Chrome 보안 DNS: 기본 켬(제공업체 "OS 기본값(가능한 경우)"), 일부 회차는 끔
- Tailscale: 실험 중 끔으로 설정. 다만 PC·Tailscale 이름에 대한 DNS 조회가 계속 기록되어 서비스 상태는 확인하지 못함
- 가상 머신 사용하지 않음. S1·S4는 로그인·입력 없이 `chatgpt.com` 첫 화면만 열었고, S2는 로그인한 상태에서 합성 문장을 입력·전송했다(개인 계정 사용, 입력한 문장은 합성 문장).
- 행동 시각은 사람이 기록해 수 초 오차가 있다.

### 2.2 실험 1 — 최초 시험 (30초)
방법: DNS 캐시를 비운 뒤 수집을 시작하고 Chrome으로 `chatgpt.com`을 열었다.

결과:
- DNS 캐시: `chatgpt.com` 2건(172.64.155.209, 104.18.32.47)
- TCP: Chrome이 172.64.155.209:443에 연결, 도메인이 DNS 캐시로 연결됨
- 그 외 도메인은 Google·Chrome 백그라운드, 백신, Microsoft 계열 등 AI와 무관

한계: 이때의 Chrome 창 종류와 실행 상태를 기록하지 못했다. 이후 같은 결과를 재현하지 못해 **조건 불명의 단발 사례**로 둔다.

### 2.3 실험 2 — Chrome 조건별 ChatGPT 접속 (6회)

| 회차 | 창 | 보안 DNS | Chrome 상태 | DNS 캐시의 chatgpt.com | 확인된 AI 관련 IP 연결 |
|---|---|---|---|---|---|
| S1_run1 | 게스트 | 켬 | 새로 시작 | 없음 | 104.18.32.47 |
| S1_run2 | 게스트 | 켬 | 새로 시작 | 없음 | 104.18.32.47 |
| S6_off_run1 | 게스트 | 끔 | 새로 시작 | 없음 | 104.18.32.47 |
| S1_normal_off_run1 | 일반 | 끔 | 새로 시작 | 없음 | 5개 모두 |
| S1_prestarted_run1 | 일반 | 켬 | 이미 실행 중 | 없음 | 172.64.155.209 외 3개 |
| S1_run3 | 일반 | 켬 | 새로 시작 | 없음 | 104.18.32.47 외 2개 |

결론: 이 PC에서는 창 종류, 보안 DNS 설정, Chrome 시작 상태를 바꿔도 DNS 캐시에 `chatgpt.com`이 나타나지 않았다. Chrome이 Windows DNS 캐시를 거치지 않고 도메인을 해석했을 가능성이 있으나, 이번 실험으로 원인을 확정하지는 못했다.

### 2.4 실험 3 — 일반 사이트 접속과 오탐 확인 (2회)

| 회차 | 연 사이트 | ChatGPT 관련 IP 5개와 일치 | Cloudflare 대역 연결 |
|---|---|---|---|
| S4_run1 | 유튜브, 대학 LMS, 할 일 앱 | 없음 | (확인 안 함) |
| S4_run2 | discord.com, medium.com, 유튜브 | 없음 | 104.18.161.117, 104.18.21.157, 104.18.32.137, 104.16.79.73 |

해석:
- 정확한 IP 일치 방식에서는 일반 사이트에서 오탐이 없었다.
- 그러나 `104.18.32.137`은 ChatGPT의 `104.18.32.47`과 같은 `104.18.32.x` 대역이다. **대역 단위로 판정하면 일반 사이트가 오탐된다.**
- Cloudflare 대역 판단은 공개 정보 확인이 필요하며 추정이다.

### 2.5 실험 4 — 로그인 상태에서 입력·전송 (S2, 각 1회)

방법: 로그인된 Chrome 일반 창에서 수행했다. 수집은 120초.
- S2a_run1: `chatgpt.com`을 열고 입력 없이 둠. 열기 약 00:53:15
- S2b_run1: 합성 문장 입력·전송, 응답 확인. 입력 시작 약 00:56:47, 전송은 그 약 3초 뒤, 응답은 다시 약 3초 뒤(사용자 기억 기준, 수 초 오차). 열기 시각은 기록하지 못했다.

| 항목 | S2a (열기만) | S2b (입력·전송) |
|---|---|---|
| ChatGPT 관련 IP 연결 | 172.64.155.209 ×1, 104.18.39.21 ×1, 172.64.148.235 ×2 | 같은 IP, 같은 횟수 |
| 연결 시점 | 열고 약 2~4초 안 | 첫 ChatGPT 연결 00:56:46, 마지막 00:56:50 |
| 이후 새 ChatGPT 연결 | 없음 | 없음 (응답 후에도) |
| Chrome 연결 전체 | 12건 | 15건 (추가분은 Google 계열) |
| DNS 캐시의 chatgpt.com | 없음 | 없음 |

해석:
- 전송으로 추정되는 시점(약 00:56:50)에 172.64.148.235 연결이 하나 있으나, S2a에도 같은 IP로 2건이 열고 나서 몇 초 안에 있었다. 입력·전송으로 늘어난 연결은 확인되지 않았다.
- 입력·전송은 이미 열린 HTTPS 연결 안에서 이뤄졌고, 새 연결만 기록하는 이 수집 방식에서는 보이지 않는 것으로 보인다.

한계: 각 1회뿐이다. S2b의 열기·전송·응답 시각이 정밀하지 않아 전송 시점과 연결 생성 시점을 초 단위로 대조할 수 없다. 패킷 크기나 트래픽량 같은 다른 근거는 확인하지 않았다.

### 2.6 AI 관련 IP 목록 기반 판정 (사후 분석)

판정 기준: Chrome이 아래 IP 5개 중 하나에 연결하면 ChatGPT 접속 후보로 본다.
- 172.64.155.209, 104.18.32.47: 최초 시험에서 `chatgpt.com` DNS 기록으로 확인됨
- 172.64.148.235, 104.18.39.21, 104.18.33.45: 접속 시각과 일치해 추정한 IP(도메인 근거 없음)

| 구분 | 결과 |
|---|---|
| ChatGPT 접속 8회(S1 6회, S2 2회) | 8/8에서 목록의 IP에 연결 |
| 그중 목록 작성에 쓰지 않은 독립 회차(S1_run3) | 1/1 탐지, 목록 밖 새 Cloudflare IP는 나타나지 않음 |
| 일반 사이트 접속 2회 | 0/2 (오탐 없음) |

한계:
- 목록은 S1 실행에서 얻었으므로 S1 5회 탐지는 독립 검증이 아니다. 독립 검증은 S1_run3(1회)과 S4(2회)뿐이다.
- 표본이 작아 정확도 수치를 일반화할 수 없다.
- Cloudflare IP는 시간과 지역에 따라 바뀔 수 있어 목록을 계속 갱신해야 한다.
- 이 매칭은 실험 후 명령으로 수행했고, PoC 본체(`collect_network.ps1`)에는 반영하지 않았다.

## 3. 결과 해석과 기술적 한계

### 3.1 확인한 사실과 확인하지 못한 사실

| 구분 | 말할 수 있는 내용 | 아직 말할 수 없는 내용 |
|---|---|---|
| DNS 캐시 | 일부 실행에서만 AI 도메인이 보이고, 이 PC의 Chrome에서는 대부분 보이지 않았다 | 누락의 원인, 다른 브라우저·앱의 동작 |
| TCP 연결 | Chrome이 ChatGPT로 보이는 Cloudflare IP에 연결했고 시각이 일치했다 | 그 IP가 ChatGPT 전용인지, 어떤 요청을 보냈는지 |
| 프로세스 | 연결한 프로세스가 `chrome`이다 | 사용자가 직접 입력했는지, 어떤 창·탭인지 |
| 접속 기록 전체 | AI 서비스 **접근** 정황 | AI **사용 행위**(입력, 파일 전송, 응답 확인) |
| 입력·전송 비교(S2, 각 1회) | 접속만 한 경우와 입력·전송한 경우의 연결 IP 종류·횟수가 같았다 | 반복 시에도 같은지, 패킷 크기·트래픽량으로 구분되는지 |

### 3.2 오탐 가능 요인
- 공용 CDN(Cloudflare) IP를 일반 사이트와 공유
- 대역 단위 판정(104.18.x 등)
- 추정한 IP 3개는 도메인 근거가 없어 다른 서비스와 겹칠 수 있음

### 3.3 미탐 가능 요인
- DNS 캐시에 기록이 남지 않는 경우(이번 실험의 주된 발견)
- Cloudflare IP 변경으로 목록이 낡는 경우
- 폴링 간격(1초)보다 짧은 연결
- VPN·프록시 사용 시 연결 목적지 변화(Tailscale 켠 상태는 실험하지 않음)

### 3.4 미수행 항목
- 다른 AI 서비스(Claude, Gemini, Copilot 등) 접속 관측
- 입력·전송 비교(S2)의 반복(각 1회만 수행), 파일 업로드 시 비교, 패킷 크기·트래픽량 기반 비교
- 검색 결과에서 AI 링크만 노출된 경우(S5), 시크릿 창(S7), DNS 캐시 잔존 시간 측정(S8)
- DNS-Client Operational 로그, Sysmon, ETW, 패킷 캡처 기반 확인
- 다른 PC·브라우저·네트워크 환경에서의 재현
- 첫 시험에서 DNS 캐시가 기록된 원인 확인

## 4. 후속 작업과 인계

### 4.1 상관분석 연동
- 04(동훈): `process_start`와 연결 이벤트의 PID·시각을 맞추면 "어떤 프로세스가 AI 후보 IP에 연결했는가"를 구성할 수 있다.
- 03(현서): 브라우저 방문 기록과 연결 시각을 대조하면 도메인 근거를 보강할 수 있다. DNS 캐시에서 도메인이 안 나오는 문제를 보완하는 역할이다.
- 01(찬웅): 입력 필드는 `observed_at`, `source`, `pid`, `process_name`, `remote_ip`, `remote_port`, `domain_from_dns_cache`, `matched_ai`를 기준으로 하되, IP 목록 매칭 필드의 추가 여부는 합의가 필요하다.

### 4.2 보고서에 사용할 결론
Windows DNS 캐시와 TCP 연결 정보를 1초 간격으로 수집해 Chrome의 ChatGPT 접속을 관측했다. 이 환경에서는 DNS 캐시에 접속 기록이 남지 않는 경우가 반복되었고, 연결 IP 목록으로는 접속 정황을 확인할 수 있었으나 공용 CDN IP로 인한 오탐 가능성과 목록 관리 부담이 있다. 네트워크 증거만으로는 질문 입력이나 파일 전송 등 실제 사용 행위를 확인할 수 없으므로, 파일·브라우저·사용자 행위 아티팩트와의 결합이 필요하다. 로그인 후 입력·전송을 한 1회와 접속만 한 1회의 연결 패턴도 같았다. 이 결과는 소규모 실험이며 일반화할 수 없다.

### 4.3 용어 정리

| 용어 | 뜻 |
|---|---|
| DNS | 도메인 이름을 IP 주소로 바꾸는 체계 |
| DNS 캐시 | 최근 조회한 도메인과 IP를 잠시 저장하는 Windows의 임시 기록 |
| DoH | DNS 질의를 HTTPS로 암호화하는 방식 |
| CDN | 여러 서비스가 함께 쓰는 콘텐츠 전송망(Cloudflare 등) |
| 폴링 | 일정 간격으로 상태를 조회하는 수집 방식 |
| PoC | 아이디어가 실제로 동작하는지 확인하는 초기 실험용 구현 |

원시 로그는 로컬에 보존했고 게시하지 않았다. PC 이름, 장치 이름, 설치된 프로그램의 도메인이 포함되어 있다. 이 문서의 IP 주소는 공개 서버 주소다.

### 4.5 주요 참고 문서
도메인·IP 대역에 관한 공식 문서 대조는 하지 않았다. Cloudflare 대역 판단은 추정이다.
