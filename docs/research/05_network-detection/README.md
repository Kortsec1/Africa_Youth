# Network Detection: 네트워크 기반 AI 사용 탐지

담당: 이채원 

## 1. 연구 목표

DNS 및 네트워크 연결 정보를 활용해 생성형 AI 서비스 접근을 식별하고, 네트워크 증거로 확인할 수 있는 AI 사용 행위의 범위를 밝힌다. "AI 서비스에 접속했다"와 "AI에 내용을 보냈다"를 구분하는 것이 핵심이다.

네트워크 기록은 팀 프로젝트가 출발점으로 삼은 "AI 서비스 접속 여부 중심 탐지"에 해당한다. 이 연구는 그 방식으로 어디까지 알 수 있는지 실험으로 확인하고, 부족한 부분을 파일·브라우저·사용자 행위 아티팩트(01~04 담당)와 결합해야 하는 근거로 연결한다.

**현재 판정:** 기본 수집 PoC와 주요 접속 실험 완료. 단일 PC(Windows 11 Home, Chrome)에서 ChatGPT 접속 위주로 수행한 소규모 실험이며, 완성된 탐지 시스템이 아니다. 다른 AI 서비스, DNS-Client 로그 기반 수집, 입력·전송 비교의 반복은 미수행이다. 상세 결과와 한계는 [results.md](results.md)에 있다.

### 주요 결과 요약

- 이 PC의 Chrome에서는 ChatGPT에 접속해도 **Windows DNS 캐시에 `chatgpt.com`이 대부분 남지 않았다.**
- **TCP 연결 기록(프로세스 + 원격 IP)** 에는 접속 때마다 ChatGPT로 보이는 Cloudflare 계열 IP 연결이 나타났다.
- 일반 사이트에서는 그 IP에 연결하지 않았지만, 같은 Cloudflare 대역의 다른 IP는 나타나 **대역 단위 판정은 오탐을 낸다.**
- 접속만 한 경우와 로그인 후 입력·전송한 경우의 연결 기록이 같아, **네트워크 연결 기록만으로는 실제 사용 행위를 구분하지 못했다.**

## 2. 기술 조사

### 2.1 AI 서비스 도메인

| 서비스 | 후보 도메인 | 관측 결과 | 오탐 위험 메모 |
|---|---|---|---|
| ChatGPT | chatgpt.com, openai.com | `chatgpt.com`을 최초 시험의 DNS 캐시에서 1회 관측. 연결 IP는 Cloudflare 계열로 보임(추정) | 공용 CDN 대역을 일반 사이트와 공유 |
| Claude | claude.ai, anthropic.com | 미수행 | |
| Gemini | gemini.google.com | 미수행 | Google 공용 인프라와 IP·도메인을 공유할 가능성 |
| 기타 | perplexity.ai 등 | 미수행 | |

- 한 서비스가 웹, API, 정적 자원, 인증에 서로 다른 도메인을 쓸 수 있다. 이번 실험에서 DNS 캐시에 남은 것은 `chatgpt.com` 하나였고, 다른 도메인은 확인하지 못했다.
- 공용 CDN·클라우드 IP를 쓰는 서비스는 IP만으로 서비스를 판별할 수 없다.

### 2.2 Windows 네트워크 정보 수집 방법

| 수단 | 얻을 수 있는 정보 | 조건 | 이 연구에서의 상태 |
|---|---|---|---|
| DNS 캐시 (`Get-DnsClientCache`) | 최근 조회한 도메인과 응답, 남은 TTL | 캐시 유지 동안만 보임 | PoC로 수집. 이 PC의 Chrome 접속은 대부분 기록되지 않음 |
| TCP 연결 목록 (`Get-NetTCPConnection`) | 원격 IP·포트, 연결한 프로세스(PID) | 조회 시점에 열려 있는 연결만 | PoC로 수집. Chrome → ChatGPT 관련 IP 연결 관측 |
| DNS-Client Operational 로그 | 질의 기록 | 기본값이 꺼져 있을 수 있음, 관리자 권한 | 미수행 |
| Sysmon (DNS 질의, 네트워크 연결 이벤트) | 질의·연결과 프로세스 | Sysmon 설치 필요 | 04번 환경에서 Sysmon 서비스가 확인되지 않아 미검증 |
| ETW | 실시간 네트워크 이벤트 | 관리자 권한, 별도 세션 | 후속 후보 |
| 브라우저 방문 기록 | URL, 방문 시각 | 브라우저별 저장 형식 | 03번 담당과 겹쳐 이 폴더에서는 다루지 않음 |

### 2.3 기술적 한계 (실험 확인 결과)

| 요인 | 영향 | 확인 결과 |
|---|---|---|
| 브라우저 보안 DNS(DoH) | Windows DNS 캐시·로그에 질의가 남지 않을 수 있음 | 켬/끔 비교에서 차이 없음(소표본). DNS 캐시 누락의 원인은 아님 |
| 브라우저 자체 DNS 처리 | 도메인 해석이 Windows DNS 캐시를 거치지 않을 수 있음 | 가능성이 있으나 원인 미확정 |
| DNS 캐시 TTL 만료 | 기록이 사라져 사후 확인 불가 | 잔존 시간 측정은 미수행 |
| 폴링 방식 연결 조회 | 새로 생긴 연결만 기록, 재사용 연결은 보이지 않음 | 입력·전송이 새 연결을 만들지 않아 구분 불가(S2) |
| 공용 CDN·IP | 다른 서비스와 구분 불가 | 대역 단위 일치는 일반 사이트를 오탐 |
| HTTPS 암호화 | 질문 내용·파일 전송 여부를 알 수 없음 | 내용은 확인 불가 |
| VPN·프록시 | 로컬 DNS 기록 자체가 달라짐 | 미수행 (Tailscale 설치됨, 실험 중 끔) |

## 5. 참고 자료

도메인과 IP 대역에 관한 공식 문서 대조는 하지 않았다. Cloudflare 대역 판단은 추정이다. 기능에 관한 문헌상 설명과 이번 실험으로 확인한 결과는 구분해서 기록한다.

## 6. 게시 원칙

원시 로그는 로컬에 보존하고, 저장소에는 선택한 필드만 남긴 요약과 합성 실험 기록을 게시한다. 실제 사용자 이름, 장치명, 절대경로, 내부 IP, 실험과 무관한 개인 접속 기록은 게시하지 않는다. 이 연구는 완성된 탐지 시스템이 아니라 네트워크 증거의 활용 가능성과 한계를 확인하는 단계다.
