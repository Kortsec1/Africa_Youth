# Network Detection: 네트워크 기반 AI 사용 탐지

담당: 채원 / 저장소 정리: 2026-11-22

## 1. 연구 목표

DNS 및 네트워크 연결 정보를 활용해 생성형 AI 서비스 접근을 식별하고, 네트워크 증거로 확인할 수 있는 AI 사용 행위의 범위를 밝힌다. "AI 서비스에 접속했다"와 "AI에 내용을 보냈다"를 구분하는 것이 핵심이다.

네트워크 기록은 팀 프로젝트가 출발점으로 삼은 "AI 서비스 접속 여부 중심 탐지"에 해당한다. 이 연구는 그 방식으로 어디까지 알 수 있는지 실험으로 확인하고, 부족한 부분을 파일·브라우저·사용자 행위 아티팩트(01~04 담당)와 결합해야 하는 근거로 연결한다.

**현재 판정:** 조사와 실험 설계 단계. 수집 PoC 작성 완료, **실험은 아직 수행하지 않았다.** 이 문서의 도메인과 수집 방법은 실측 전 후보이며, 실험 결과는 [results.md](results.md)에 기록한다.

## 2. 기술 조사

### 2.1 AI 서비스 도메인 (실측 전 후보)

아래 도메인은 서비스 이용 시 관측될 것으로 예상하는 후보이며, 실험 1~3에서 실제로 관측된 도메인만 확정한다. 확정 결과는 results.md에 기록한다.

| 서비스 | 후보 도메인 | 관측 여부 | 오탐 위험 메모 |
|---|---|---|---|
| ChatGPT | chatgpt.com, openai.com | 미확인 | 정적 자원·API 도메인이 따로 있을 수 있음 |
| Claude | claude.ai, anthropic.com | 미확인 | |
| Gemini | gemini.google.com | 미확인 | Google 공용 인프라와 IP·도메인을 공유할 가능성 |
| Copilot | copilot.microsoft.com | 미확인 | Windows·Edge가 백그라운드로 접속할 가능성 |
| 기타 | perplexity.ai 등 | 미확인 | |

- 한 서비스가 웹, API, 정적 자원, 인증에 서로 다른 도메인을 쓸 수 있다. 어떤 도메인이 "사용"의 신호이고 어떤 것이 단순 로딩인지 실험으로 구분한다.
- 공용 CDN·클라우드 IP를 쓰는 서비스는 IP만으로 서비스를 판별할 수 없다. 도메인 정보가 필요하다.

### 2.2 Windows 네트워크 정보 수집 방법

| 수단 | 얻을 수 있는 정보 | 조건 | 이 연구에서의 상태 |
|---|---|---|---|
| DNS 캐시 (`Get-DnsClientCache`) | 최근 조회한 도메인과 응답, 남은 TTL | 캐시 유지 동안만 보임 | PoC 포함, 실험 전 |
| TCP 연결 목록 (`Get-NetTCPConnection`) | 원격 IP·포트, 연결한 프로세스(PID) | 조회 시점에 열려 있는 연결만 | PoC 포함, 실험 전 |
| DNS-Client Operational 로그 | 질의 기록 | 기본값이 꺼져 있을 수 있음, 관리자 권한 | 선택 실험. 채널 이름과 이벤트 구조는 실제 환경에서 확인 필요 |
| Sysmon (DNS 질의, 네트워크 연결 이벤트) | 질의·연결과 프로세스 | Sysmon 설치 필요 | 04번 환경에서 Sysmon 서비스가 확인되지 않아 우선순위 낮음 |
| ETW | 실시간 네트워크 이벤트 | 관리자 권한, 별도 세션 | 후속 후보 |
| 브라우저 방문 기록 | URL, 방문 시각 | 브라우저별 저장 형식 | 03번 담당과 겹쳐 이 폴더에서는 다루지 않음 |

### 2.3 예상되는 기술적 한계 (검증 대상)

| 요인 | 예상 영향 | 확인 방법 |
|---|---|---|
| 브라우저 보안 DNS(DoH) | Windows DNS 캐시·로그에 질의가 남지 않을 수 있음 | 실험 6: 켬/끔 비교 |
| 브라우저 자체 DNS 캐시 | 재접속 시 새 질의가 안 생김 | 매 실행 전 브라우저 재시작 |
| DNS 캐시 TTL 만료 | 기록이 사라져 사후 확인 불가 | 실험 8: 잔존 시간 측정 |
| 폴링 방식 연결 조회 | 짧은 연결을 놓침 | 폴링 간격별 누락 확인 |
| 공용 CDN·IP | 다른 서비스와 구분 불가 | 일반 사이트 비교 |
| HTTPS 암호화 | 질문 내용·파일 전송 여부를 알 수 없음 | 확인 가능 범위 표로 정리 |
| VPN·프록시 | 로컬 DNS 기록 자체가 달라짐 | 후속 후보 |

## 3. 프로젝트 적용 가능성과 산출물

- [실험 결과](results.md): 실험 방법, 결과, 오탐·한계. 실험 후 작성
- [PoC 코드](poc/): `collect_network.ps1`(DNS 캐시·TCP 연결 수집), `export_dns_log.ps1`(DNS-Client 로그 내보내기, 선택)
- [실험 절차서](protocol.md): 시나리오 S0~S8, 정답 시각 기록표

### 다른 담당과의 연동 계획

| 담당 | 연동 내용 |
|---|---|
| 04 동훈 | `process_start` 이벤트와 PID·시각으로 연결해 "어떤 프로세스가 어떤 AI 도메인에 접속했는가"를 구성 |
| 03 현서 | 브라우저 방문 기록과 DNS 기록의 시각 대조 |
| 01 찬웅 | 타임라인·상관분석 입력 필드 형식 합의 |

PoC 출력은 JSONL이며 `schema_version`, `source`, `observed_at`, `domain`, `pid`, `process_name`, `remote_ip`, `matched_ai`, `evidence_level` 필드를 쓴다. 필드는 01번과 합의되면 맞춘다.

## 6. 게시 원칙

원시 로그는 로컬에 보존하고, 저장소에는 선택한 필드만 남긴 요약과 합성 실험 기록을 게시한다. 실제 사용자 이름, 장치명, 절대경로, 내부 IP, 실험과 무관한 개인 접속 기록은 게시하지 않는다. 이 연구는 완성된 탐지 시스템이 아니라 네트워크 증거의 활용 가능성과 한계를 확인하는 단계다.
