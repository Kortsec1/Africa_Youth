# 기술 조사

## 1. Shadow AI 탐지 기술 및 한계

### 1.1 기존 접근 방식

| 계층 | 대표 방식 | 볼 수 있는 것 | 한계 |
|---|---|---|---|
| 네트워크 | 프록시·SWG URL 필터, DNS 로그, CASB | 어떤 AI 도메인에 언제 접속했는가 | TLS 로 내용 불가시, 사내망 밖(재택·핫스팟)·DoH 우회, 로컬 LLM 은 트래픽 없음 |
| SaaS/계정 | CASB API 연동, SSO 로그 | 회사 계정 사용 여부 | 개인 계정 사용은 보이지 않음 |
| 엔드포인트 DLP | 클립보드·업로드 차단, 콘텐츠 검사 | 민감 데이터 이동 시점 | 고비용·정책 위주, 사후 '재구성'보다 '차단' 목적, 오탐 많음 |
| EDR | 프로세스·네트워크 텔레메트리 | 데스크톱 앱·스크립트·API 호출 | 브라우저 내부 행위(어떤 탭에서 무엇을)는 거의 안 보임 |
| **포렌식(본 프로젝트)** | 파일시스템·LNK·브라우저 DB·이벤트 로그 | 사후에 "사용 전후 무엇을 했는가" | 아티팩트 보존 기간, 시간 정밀도, 사용자 조작(삭제·시크릿 모드) |

### 1.2 본 프로젝트의 차별점
- 기존 방식은 대부분 **"AI 에 접속했는가"**(Yes/No)를 답한다.
- 본 프로젝트는 AI 사용 구간을 **기준점(anchor)** 으로 두고, 그 전후의 파일 열람·클립보드·업로드·다운로드·실행·삭제를
  연결해 **"무엇을 가지고 들어가서, 무엇을 가지고 나왔는가"** 를 증거 기반으로 설명한다.

### 1.3 근본적 한계 (설계에 반영)
1. **붙여넣기·입력 내용은 OS 아티팩트로 남지 않는다.** 클립보드 변경 + AI 창 전환은 '정황'까지만 가능 (SAI-003).
   04 실측에서도 '복사 → ChatGPT 이동 후 붙여넣기 함/안 함'이 Windows 수집기 기록상 구분되지 않았고,
   복사 1회·붙여넣기 3회가 클립보드 알림 1건으로 기록됐다 ([04 results §2.3~2.4](../04_endpoint-telemetry/results.md)).
   반면 웹에서는 Chrome 확장의 `paste` 이벤트가 붙여넣기 1건/대조 0건으로 일치해, 엔진은 이를 직접 근거로 사용한다.
2. **업로드 자체를 직접 증명하는 로컬 아티팩트가 약하다.** 파일 선택 대화상자·LNK·업로드 엔드포인트 통신의 시간 일치로 추정 (SAI-004).
3. **타임스탬프 의미가 아티팩트마다 다르다.** LNK 수정시각 = 마지막 열람, $SI 수정시각 = 내용 수정(복사 시 원본 시각 유지) 등 → 스키마에 `time_meaning` 필드를 강제.
4. **조작 가능성.** $SI 타임스톰핑, 히스토리 삭제, 시크릿 모드. → 출처별 신뢰도 가중치 + 독립 출처 교차 확인.

## 2. 이벤트 정규화 및 Timeline 구조 설계

모든 아티팩트를 아래 하나의 이벤트 모델로 변환한다 (`src/shadow_ai_forensics/schema.py`).

| 필드 | 설명 | 예 |
|---|---|---|
| `ts` | UTC 기준 시각 (내부 통일, 출력 시 KST 병기) | 2026-11-10T05:01:19Z |
| `source` | 아티팩트 종류 | MFT, USN, LNK, JumpList, ChromeHistory, ChromeDownloads, Sysmon, DNSClient, Agent |
| `category` / `action` | 행위 분류 | file / `file_open`, web / `download`, clipboard / `clipboard_change` |
| `time_meaning` | **이 시각이 무엇의 시각인지** | "LNK 생성시각 ≈ 대상 파일 최초 열람" |
| `process`, `pid` | 행위 주체 | chrome.exe |
| `path` / `url` / `domain` / `title` | 행위 대상 | |
| `raw_ref` | 원본 파일:행 번호 (재현·검증용) | `lnk.csv:5` |
| `attrs` | 출처별 부가 정보 | Zone.Identifier HostUrl, 다운로드 tab_url 등 |
| `ai_service`, `ai_role`, `sensitive`, `tags` | enrichment 결과 | ChatGPT / upload / true / `origin:ai` |

**시간 처리 규칙**
- Chromium: 1601-01-01 기준 µs, Firefox: Unix epoch µs, FILETIME: 1601 기준 100ns, EZ Tools CSV: UTC 문자열(7자리 소수) → 모두 UTC `datetime`.
- 서로 다른 출처의 동일 행위(예: USN FileDelete 와 Sysmon EID 26)는 **지우지 않고** 규칙 단계에서 묶어 교차 확인 증거로 쓴다.

**AI 서비스 카탈로그** (`src/shadow_ai_forensics/data/ai_services.toml`)
- 도메인마다 역할(`chat`/`upload`/`api`/`static`/`corporate`)을 부여한다. `openai.com/news` 방문 같은 **회사 홈페이지 방문은 사용으로 세지 않는다** (오탐 방지).

## 3. 상관분석 방식 조사

| 방식 | 내용 | 장점 | 단점 | 채택 |
|---|---|---|---|---|
| 슈퍼 타임라인 (plaso) | 모든 이벤트를 시간순 나열 | 누락 없음 | 분석가가 직접 해석, 대량 노이즈 | 출력물로 제공 |
| 고정 시간창 | 기준 이벤트 ±N분 내 이벤트 연결 | 단순·설명 가능 | 창 크기에 민감 | **채택** (규칙별 창 크기 분리) |
| 세션 기반 | 기준 이벤트를 gap 기준으로 세션화 후 세션 전후 분석 | 사용 '구간'을 표현 | gap 설정 필요 | **채택** (gap 10분) |
| 시퀀스/상태기계 | A→B→C 순서 패턴 매칭 (Sigma correlation, EQL sequence) | 공격 흐름 표현 | 규칙 작성 복잡 | 일부 채택 (복사→전환, 대화상자→LNK→업로드, 다운로드→실행) |
| 엔터티 그래프 | 파일·프로세스·URL 을 노드로 연결 | 다단계 연결 | 구현·시각화 비용 | 향후 과제 (경로 정규화로 파일 단위 연결은 구현) |
| ML 이상탐지 | 사용자 행위 기준선 대비 이탈 | 미지 패턴 | 설명 가능성 낮음, 학습 데이터 필요 | 미채택 (포렌식은 설명 가능성 우선) |

**채택 구조**: ① AI 관련 이벤트로 세션 구성 → ② 세션 시간창 안에서 규칙별 시퀀스 매칭 → ③ 파일 경로 정규화(`.\Users\..` ↔ `C:\Users\..`)로 출처 간 같은 파일 연결 → ④ 앞 규칙 결과를 뒤 규칙이 참조 (예: 업로드된 파일이 압축 파일이면 SAI-008 상향, 업로드/다운로드 파일이 삭제되면 SAI-009).

## 6. 증거와 추론의 구분 및 오탐 가능성

### 6.1 구분 원칙
모든 탐지 결과(Finding)는 네 부분으로 나뉘어 출력된다.

| 구분 | 정의 | 예 (SAI-004) |
|---|---|---|
| **확인된 사실** | 특정 아티팩트의 특정 행에서 그대로 읽히는 내용 + 원본 위치 | "14:04:25 `영업자료_고객DB.zip` LNK 생성 [lnk.csv:5]" |
| **추론** | 사실들의 시간·논리 결합으로 도출한 해석 | "파일 선택창에서 zip 을 선택해 ChatGPT 에 업로드한 것으로 추정" |
| **다른 가능성** | 같은 사실을 설명하는 정상 행위 | "선택 후 업로드 취소" |
| **확정에 필요한 증거** | 추론을 사실로 올리려면 필요한 것 | "SRUM 업로드 바이트, 프록시 로그" |

### 6.2 신뢰도 산정
`신뢰도 = 규칙 기본값 + 독립 출처 교차 확인 가산 + 강한 단서 가산 − 약한 근거 감산`, 상한 0.95.
- 독립 출처: Sysmon DNS 와 DNS-Client 는 같은 관찰이므로 하나로 센다.
- DNS 만 있는 세션은 0.45 로 시작 (프리페치·백그라운드 갱신 가능).
- 1.0(확정)은 부여하지 않는다 — 포렌식 결론은 정황의 강도로 표현.

### 6.3 오탐 요인과 대응
| 오탐 요인 | 영향 규칙 | 대응 |
|---|---|---|
| AI 회사 홈페이지·문서 방문 | SAI-001 | 도메인 역할 `corporate` 는 세션 제외 (테스트로 검증) |
| 브라우저 탭 복원·프리페치 | SAI-001 | 창 포커스·방문 기록 등 사용자 조작 증거가 없으면 신뢰도 하향 |
| 병행 업무 중 무관한 문서 열람 | SAI-002 | 단독으로는 low/medium, 다른 규칙과 결합 시에만 의미 부여 |
