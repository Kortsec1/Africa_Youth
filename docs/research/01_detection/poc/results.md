# 상관분석 실험 결과 및 한계

## 1. 실험 환경 및 목적

- 수행 주체: Codex 실행 환경
- Python: 3.14.6
- 외부 패키지: 없음
- 데이터: 직접 작성한 가상 이벤트
- 정책: demo-v1
- 기본 시간 범위: 60초
- 반복 방문 기준: 3회

사용자 PC에서는 아직 재실행하지 않았다.
실제 Windows 로그 수집이나 AI 서비스 사용 실험은 수행하지 않았다.

목적은 규칙 R01~R05의 출력이 사전에 정의한 시나리오와 일치하는지 확인하는 것이다.

## 2. 실행 방법

poc/ 폴더에서 실행한다.

```sh
python3 analyze.py sample_events.json > output.json
python3 test_analyze.py
```

## 3. 실제 관찰 결과

### 샘플 4건 분석

Timeline: evt-001 → evt-002 → evt-003 → evt-004

| 규칙 | 결과 | 근거 |
|---|---|---|
| R01 | 3건 | evt-002, evt-003, evt-004 각각 |
| R02 | 1건 | evt-001과 evt-003 |
| R03 | 0건 | 같은 그룹의 반복 횟수 부족 |
| R04 | 0건 | 샘플 서비스의 정책이 존재 |
| R05 | 1건 | evt-001과 사용자 미확인 evt-004 |

규칙별 결과는 중복될 수 있으며 독립된 사용자 행위 건수가 아니다.

### 자동 검증

7개 테스트 메서드가 모두 통과했다.
그중 test_scenarios는 rules.md의 T01~T13을 하위 사례로 검사한다.

추가로 확인한 항목:
- 뒤섞인 입력의 정렬과 동일 이벤트 중복 제거
- 같은 ID의 다른 내용 거부
- 시간대가 없는 시각 거부
- R02의 시간 범위 비교: 40초 차이는 30초 설정에서 불일치, 60·300초에서 일치
- R03의 겹치는 일치 구간 병합과 분리된 구간 구분
- 정책 적용 전 시각의 unknown 처리
- 두 사용자 값이 모두 누락되어도 R02로 연결하지 않음

## 4. 해석 및 한계

정의한 가상 사례에서 예상 판정과 코드 출력이 일치했다.
이 결과는 실제 환경의 탐지율·오탐률 또는 업로드 탐지 성공을 의미하지 않는다.

- 실제 데이터의 수집 오류·식별자 매핑·시각 오차는 검증하지 않았다.
- 새로고침·자동 방문은 R03에도 일치할 수 있다.
- R02는 시간·장치·사용자 관계만 평가하며 파일 전송을 입증하지 않는다.
- 입력 스키마 전체 검증과 성능 최적화는 아직 구현하지 않았다.
- 시간만 사용한 분석과 식별자·순서 조건을 추가한 분석의 전체 비교 실험은 미수행이다.
