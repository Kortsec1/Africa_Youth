# 탐지 규칙 및 검증 시나리오

## 1. 목적과 현재 상태

가상 이벤트에 적용할 규칙 5개와 예상 판정을 정의한다.
아래 내용은 설계이며, 실행 결과가 아니다.

기존 sample_events.json은 구조 설명용이다.
규칙별 실험 데이터와 승인 정책은 구현 단계에서 추가한다.

## 2. 공통 조건

- 시간 범위 W는 기본 60초이며, 30초·300초와 비교한다.
- 경계값은 포함한다: 시간 차이가 W와 같으면 범위 내로 처리한다.
- 순서 규칙은 앞 이벤트의 시각이 엄격히 빠른 경우에만 일치한다.
- 필수 연결 키가 null이면 두 값이 모두 null이어도 일치로 처리하지 않는다.
- 중복 event_id는 입력 처리 단계에서 제거하거나 충돌로 분리한다.
- 서비스 승인 상태는 이벤트 발생 시점의 정책으로 판단한다.
- 정책이 없으면 unknown이며, unapproved로 취급하지 않는다.

초기 정책은 서비스 단위로 단순화한다.
승인된 서비스의 사용 목적이나 데이터 취급 적절성까지 판단하지 않는다.

## 3. 출력 구분

| 구분 | 의미 |
|---|---|
| policy_review | 미승인 서비스 접근 관련 검토 대상 |
| context_review | 접근 전후의 관련 행위 검토 대상 |
| insufficient_context | 정책 또는 연결 정보가 부족함 |
| no_match | 해당 규칙의 조건에 일치하지 않음 |

no_match는 안전하거나 AI를 사용하지 않았다는 의미가 아니다.
하나의 이벤트 묶음이 여러 규칙에 일치할 수 있다.

## 4. 규칙 정의

### R01. 미승인 AI 서비스 방문 기록

조건:
- event_type = ai_service_access
- observation_kind = browser_visit
- 해당 시점의 승인 상태 = unapproved

출력: policy_review

확인한 사실:
- 미승인으로 설정된 서비스의 방문 기록이 존재한다.

판단 한계:
- 질문 전송, 로그인, 업로드 또는 직접 조작 여부는 확인하지 못한다.

### R02. 파일 접근 후 미승인 AI 서비스 방문

조건:
- file_access의 access_kind = read_data
- 이후 ai_service_access의 observation_kind = browser_visit
- 두 이벤트의 device_id와 user_id가 일치하며 null이 아님
- 0 < 방문 시각 - 파일 접근 시각 <= W
- 방문 시점의 서비스 승인 상태 = unapproved

출력: context_review

확인한 사실:
- 같은 장치·사용자에 귀속된 파일 읽기와 서비스 방문 기록이 순서대로 존재한다.

추론:
- 파일 활동과 서비스 접근 사이에 관련성이 있을 가능성이 있다.

판단 한계:
- 읽은 파일이 업로드되었거나 사람이 파일 내용을 확인했다고 확정하지 않는다.

### R03. 미승인 AI 서비스 반복 방문

조건:
- observation_kind = browser_visit인 ai_service_access
- device_id, user_id, service_id가 동일하고 null이 아님
- 각 방문 시점의 승인 상태 = unapproved
- W 이내에 서로 다른 event_id가 3개 이상 존재

출력: policy_review

처리 방식:
- 각 방문 시각 t를 기준으로 [t-W, t] 구간을 검사한다.
- 같은 그룹에서 겹치는 일치 구간은 하나의 탐지 결과로 합친다.
- 합쳐진 결과에도 실제 조건을 만족한 구간과 근거 이벤트를 보존한다.

판단 한계:
- 반복 방문은 반복 질문이나 활발한 AI 사용을 의미하지 않는다.
- 새로고침·자동 이동 등으로 기록이 늘어날 수 있다.
- 횟수 3회는 실험용 기준이며 검증된 위험 기준이 아니다.

### R04. 승인 상태를 확인할 수 없는 AI 접근

조건:
- event_type = ai_service_access
- 해당 시점의 승인 상태 = unknown

출력: insufficient_context

확인한 사실:
- 접근 관련 기록은 있으나 적용할 승인 정책이 없다.

판단 한계:
- 미승인 사용이나 정상 사용으로 분류하지 않는다.
- DNS 질의 등 약한 관찰도 포함할 수 있으므로 observation_kind를 함께 출력한다.

### R05. 사용자 식별 부족으로 연결할 수 없는 행위

조건:
- read_data 파일 접근 후 browser_visit 기록이 존재
- device_id가 동일
- 0 < 방문 시각 - 파일 접근 시각 <= W
- 두 이벤트 중 하나 이상의 user_id가 null

출력: insufficient_context

확인한 사실:
- 같은 장치에서 시간적으로 가까운 두 기록이 존재한다.

판단 한계:
- 같은 사용자의 행위로 연결하지 않는다.
- 이 규칙은 위험 행위 탐지보다 상관분석의 정보 부족을 표시하기 위한 규칙이다.
- 두 사용자 ID가 알려져 있고 서로 다르면 이 규칙은 일치하지 않는다.

## 5. 규칙별 검증 시나리오

아래 시간은 가상 시나리오 내 상대 시각이다.
각 행은 독립된 입력으로 실행하며 W=60초를 사용한다.

| 사례 | 입력 | 예상 판정 |
|---|---|---|
| T01 | 승인된 서비스 방문 1건 | R01 불일치 |
| T02 | 미승인 서비스 방문 1건 | R01 일치 |
| T03 | 같은 장치·사용자의 파일 읽기 후 40초에 미승인 서비스 방문 | R02 일치 |
| T04 | 파일 읽기와 방문의 장치가 다름 | R02 불일치 |
| T05 | 같은 장치지만 서로 다른 사용자의 파일 읽기와 방문 | R02 불일치 |
| T06 | 같은 장치·사용자의 파일 읽기 후 61초에 방문 | R02 불일치 |
| T07 | 방문 후 10초에 파일 읽기 | R02 불일치 |
| T08 | 같은 장치·사용자·미승인 서비스 방문이 0·20·40초에 발생 | R03 일치 |
| T09 | 위 조건에서 방문이 0·20초에만 발생 | R03 불일치 |
| T10 | 정책이 없는 서비스 접근 | R04 일치 |
| T11 | 같은 장치에서 파일 읽기 후 40초에 방문, 방문 사용자 누락 | R05 일치, R02 불일치 |
| T12 | 같은 장치·사용자의 파일 읽기 후 정확히 60초에 미승인 서비스 방문 | R02 일치 |
| T13 | 파일 읽기와 방문의 발생 시각이 동일 | R02 불일치 |

각 사례는 표시된 규칙을 기준으로 평가한다.
예를 들어 T03은 R02 외에 R01에도 일치할 수 있다.
전체 예상 규칙 목록은 구현 단계의 정답 데이터에 명시한다.

## 6. 증거와 추론의 평가

초기에는 임의의 확률 점수 대신 다음 판단 수준을 기록한다.

| 판단 수준 | 적용 기준 |
|---|---|
| 단일 기록 | 하나의 원본 관찰을 설명함 |
| 상관 정황 | 필수 연결 키·시간·순서 등의 조건으로 여러 기록을 연결함 |
| 판단 보류 | 정책이나 필수 식별 정보가 부족함 |

R01은 단일 기록, R02·R03은 상관 정황,
R04·R05는 판단 보류로 표시한다.

이는 탐지 정확도나 위험도 순위가 아니다.
여러 이벤트가 일치하더라도 관찰하지 못한 업로드를 확정할 수 없다.

실제 로그 연동 단계에서는 수집원 신뢰성, 시각 오차,
사용자 매핑과 로그 누락 여부를 추가 평가한다.

## 7. 탐지 결과에 남길 정보

- rule_id: 일치한 규칙
- category: 출력 구분
- assessment_level: 판단 수준
- evidence_ids: 근거 이벤트 ID 목록
- observed_facts: 기록에서 확인한 사실
- inference: 도출한 추론. 없으면 null
- limitations: 확인할 수 없는 내용
- policy_version: 적용 정책 버전. 정책이 없으면 null
- parameters: 적용 시간 범위와 횟수 기준

가상 입력에서 관찰한 사실은 실제 사용자 행위의 증거가 아니다.
모든 실험 출력에 가상 데이터 기반 결과임을 표시한다.
