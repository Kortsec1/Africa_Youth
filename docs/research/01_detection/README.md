# Shadow AI 탐지 모델 및 상관분석

## 1. 연구 목표

Windows 이벤트와 포렌식 아티팩트를 공통 구조로 정리하고,
관련 기록을 연결하여 Shadow AI 사용 정황과 사용자 행위의 흐름을 분석한다.

본 연구에서 Shadow AI는 조직의 승인 정책을 벗어난 AI 사용을 뜻한다.
AI 서비스 접근 여부와 정책 위반 여부는 별도로 판단한다.

초기에는 가상 이벤트를 이용한 규칙 기반 상관분석 PoC를 구현한다.
탐지 결과에는 근거 이벤트, 추론 내용, 판단 한계를 함께 제시한다.

## 2. 담당 범위

### 수행할 작업

- 기존 Shadow AI 탐지 기술과 한계 조사
- 이벤트 정규화 및 통합 Timeline 구조 설계
- 이벤트 상관분석 방식 조사
- 탐지 규칙 및 시나리오 5개 이상 정의
- 증거와 추론의 구분 및 신뢰도 평가 기준 설계
- 가상 이벤트 기반 상관분석 PoC 구현·실행
- 정상·의심 행위 비교 및 오탐·미탐 분석
- 분석 시스템 구조도 작성

### 다른 담당과의 구분

파일 시스템 아티팩트 분석, AI 서비스 사용 흔적 수집,
실시간 이벤트 수집기 및 네트워크 탐지기 구현은 각 담당이 수행한다.

담당 1은 해당 데이터의 의미와 한계를 참고하여
공통 입력 구조와 상관분석 규칙을 설계한다.
팀원의 결과가 없어도 가상 이벤트로 독립적으로 실험하며,
실제 로그 연동은 이후 통합 단계에서 검증한다.

## 3. 관련 기술 및 동작 원리

### 3.1 기존 탐지 기술

| 기술 | 동작 원리 | 활용 가능성 및 한계 |
|---|---|---|
| AI 서비스 발견 | 접속 정보를 알려진 AI 앱 목록과 비교 | 서비스 접근 식별에 활용. 질문·업로드 여부는 별도 증거 필요 |
| DLP 기반 행위 감사 | 정책 대상 데이터의 업로드·붙여넣기 등을 관찰·제어 | 구체적인 행위의 근거로 활용. 지원 환경과 정책 설정에 의존 |
| 이벤트 상관분석 | 여러 이벤트를 식별자·시간·순서 조건으로 연결 | 행위 흐름 재구성에 활용. 이벤트 연결만으로 인과관계가 입증되지는 않음 |

Microsoft의 Shadow AI discovery는 클라우드 앱 카탈로그를 이용해
사용자가 접근한 생성형 AI SaaS 앱을 식별한다.[1]

Endpoint DLP는 지원 환경에서 업로드·붙여넣기 등의 행위를
정책에 따라 감사하거나 제한한다.[2]
정책상 허용과 실제 전송 완료는 구분해야 한다.

본 연구에서는 이러한 탐지·감사 결과를 입력 후보로 보고,
여러 기록을 연결하는 상관분석 로직을 구현한다.
현재 조사는 대표 방식에 대한 기초 조사이며,
전체 제품의 탐지 성능을 비교한 결과는 아니다.

### 3.2 상관분석 방식

| 방식 | 연결 조건 | 연구용 예시 | 주의점 |
|---|---|---|---|
| 시간 범위 기반 | 일정 시간 안에 관련 이벤트 발생 | 파일 접근과 AI 접속이 60초 이내 발생 | 우연히 인접한 행위를 연결할 수 있음 |
| 식별자 기반 | 장치·사용자·프로세스 등 연결 키 일치 | 같은 장치와 사용자의 기록 연결 | 같은 사용자라도 무관한 작업일 수 있음 |
| 순서 기반 | 연결 조건을 만족하며 정해진 순서로 발생 | 파일 접근 → AI 접속 | 순서가 일치해도 업로드를 의미하지 않음 |
| 횟수 기반 | 일정 시간 내 이벤트 수가 기준 이상 | 미승인 AI 접근 기록 반복 | 자동 통신·중복 수집을 구분해야 함 |

Sigma Correlation은 group-by와 timespan을 이용한 그룹화·시간 범위,
event_count를 이용한 횟수,
temporal 및 temporal_ordered를 이용한 시간·순서 조건을 표현한다.[3]

Elastic EQL은 sequence, by, maxspan을 사용해
공통 식별자와 제한된 시간 범위 내의 이벤트 순서를 검색한다.[4]

초기 PoC에서는 식별자·시간 범위·순서 조건을 조합한다.
Sigma와 EQL은 설계 참고 자료로 활용하고,
실행에 반드시 필요한 도구로 두지는 않는다.

## 4. 분석 원칙

- 직접 관찰한 사실과 규칙으로 도출한 추론을 분리한다.
- 서비스 접근만으로 질문 전송이나 파일 업로드를 확정하지 않는다.
- 시간적으로 가까운 이벤트라도 장치·사용자 등 연결 조건을 확인한다.
- 규칙에 필요한 식별자가 없으면 일치로 처리하지 않는다.
- 승인 상태를 approved, unapproved, unknown으로 구분한다.
- 정책 정보가 없으면 미승인 사용으로 단정하지 않는다.
- 근거가 부족하면 판단 불가 또는 추가 확인 필요로 표시한다.
- 신뢰도 등급을 검증된 확률이나 정확도처럼 표현하지 않는다.
- 가상 데이터 실험 결과를 실제 환경의 탐지 성능으로 일반화하지 않는다.

## 5. 초기 설계 및 실험 계획

### 5.1 분석 흐름

이벤트 입력 → 정규화 → Timeline 생성 → 연결 조건 검사
→ 탐지 규칙 적용 → 근거·추론·판단 한계 출력

Python으로 초기 PoC를 구현할 계획이다.
공통 이벤트 구조, 개별 규칙과 신뢰도 기준은 다음 단계에서 정의한다.

### 5.2 상관분석 예시

같은 장치·사용자의 파일 접근 후 일정 시간 안에
미승인 AI 서비스 접근 기록이 존재하면
“파일 활동을 동반한 미승인 AI 접근 정황”으로 분류한다.

- 근거: 파일 접근 기록과 AI 서비스 접근 기록
- 연결 조건: 장치·사용자 일치, 시간 범위, 발생 순서
- 추론: 두 행위가 관련되었을 가능성
- 한계: 해당 파일의 업로드 여부는 확인할 수 없음

위 예시는 설계안이며, 구현하거나 실험으로 검증한 규칙은 아니다.

### 5.3 실험 방법

시나리오별 가상 이벤트와 예상 판정을 먼저 작성하고,
상관분석 코드의 실제 출력과 비교한다.

동일한 입력에 다음 조건을 적용해 결과 차이를 확인한다.

1. 시간 조건만 적용
2. 시간 + 장치·사용자 조건 적용
3. 시간 + 장치·사용자 + 순서 조건 적용

시간 범위는 30초·60초·300초를 실험용 후보로 비교한다.
검증된 기준값으로 취급하지 않는다.

### 5.4 주요 검증 항목

- 정상 사용과 미승인 사용의 구분
- 서로 다른 장치·사용자 이벤트의 잘못된 연결
- 시간 범위 변경에 따른 결과 차이
- 이벤트 누락·중복·순서 뒤바뀜의 영향
- 파일 활동과 AI 접근을 업로드로 오인하는지 여부
- 탐지 결과에서 원본 이벤트를 추적할 수 있는지 여부

실험 환경, 입력 데이터, 규칙 버전, 실행 명령과 실제 출력을 기록한다.
가상 데이터에는 실제 Windows 수집 기록과 구분되는 표시를 남긴다.

## 7. 프로젝트 적용 가능성

각 담당의 수집 결과를 공통 이벤트 구조로 변환하여
사용자 행위 Timeline과 규칙 기반 탐지 결과를 제공하는 데 활용한다.

탐지 결과에는 관련 이벤트와 판단 과정을 함께 제시하여,
분석자가 확인된 사실과 추가 확인이 필요한 부분을 구분하도록 한다.

초기에는 가상 데이터에서 구현과 규칙의 동작을 검증한다.
이후 통합 단계에서 실제 로그의 필드 차이와 누락을 반영해 추가 검증한다.
